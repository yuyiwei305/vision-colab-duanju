# H3 分镜、视频提示词与专项审查

[项目版 forest-laoli-h3](../../.agents/skills/forest-laoli-h3/SKILL.md) 是 H3 的专项技能。主编排和各阶段文档 owner 沿用 `short-drama`。项目只加载本地收敛版；全流程导演、固定九图、首尾帧模式、另出投喂包及逐阶段等待确认的内容未进入项目版。原始仓库保留追溯。

明确要求 H3，或作品生效视频档案为 H3（无另定路线的新视频任务按项目默认 H3），且任务涉及分镜、视频提示词或 H3 专项审查时，**先实际读取阶段技能，再运行下面对应的命令，读取输出并落实到正式文档或审查**。整个流程命中多个阶段就分别调用；局部改稿、续做和只做审查也适用。已读取且版本未变的内容可在本会话复用。纯剪辑和恢复原批次不重跑创作。

```bash
python3 scripts/h3_production.py skill --stage storyboard
python3 scripts/h3_production.py skill --stage prompts
python3 scripts/h3_production.py skill --stage review
```

项目入口负责触发。分镜、提示词各自写回 `分镜.md`、`视频提示词.md`；专项审查用 `short-drama-review` 定位问题，修订回对应 owner。技能文件缺失或不可读，暂停依赖它的步骤。单阶段仅记录实际完成的阶段和镜头；不补写没有执行的阶段。

**分镜开始前**读 [段落契约](shot-motion-contract.md)。正式关系为 Sequence → Motion → Shot。先定观众看到的动作、切点与声音，再决定每次请求包含哪些镜头。

默认使用可复用资产。图、音频及混合输入容量见[运行清单](workflow-v4-g4-runtime.json)的 `capabilities`。完全独立 Motion 的起镜符合[冲击帧条件](shot-motion-contract.md#冲击帧与-h3-构图参考)时，可用一张 `用途：构图` 的 `reference_image`，占本段参考图的一槽。分镜与视频提示词同步同一 REF。AV latent 续接链首与后续段均不挂构图图。

逐场检查同一时空中需要动作或同机位/自然运镜连续的相邻生成段：优先形成真实 AV latent 链；单段已完整承载、正反打或需要切换时空/视角时可独立切镜并在分镜写明理由。对照正式 `续接来源` 和预览的 `continue_from_job`、净帧及分片；只有上下文档位、人物地点图或参考音色不等于实际续接。取回后以官方 job、实际生成图、前段 latent 回执及 SHA 核对，并在剪辑单记录实际采用的版本；不得把技术完成当声画验收。

## 场内续接自动规划

MOTION 写 `入段：独立` 或 `入段：续接`。后者从同一 Sequence 的上一 MOTION 读取实际音视频潜变量；无需额外挂尾帧。MOTION 内部的切镜写在提示词。

新 H3 任务由当前代理在分镜和视频提示词阶段自动完成，**先于专项快照和 GPU 分配**。在 `分镜.md` 写清各 SHOT 的 `来源`、`景别/机位`、`运镜`、`起点`、`终点` 和逐段映射；在 `视频提示词.md` 写各 MOTION 的本段状态和 `续接来源：自动`。自动规划落实镜头决策，不能代替判断切点和接缝。

```bash
# 建议一次规划整集，再按完整续接链分批；不会调用模型或申请 GPU。
python3 scripts/h3_production.py continuity --project '<作品目录>' --episode EP001
python3 scripts/h3_production.py continuity --project '<作品目录>' --episode EP001 --apply
```

- 新格式依据分镜的「入段」字段确定续接。续接起镜承接前段实际状态；本次请求若还含其他镜头，按契约写实际切点和请求时钟。旧格式按原规则读取。
- 不够确定、当前范围缺少前段或构图参考与续接冲突时，规划显示待判断，`--apply` 不写入任何条目。当前代理回读剧本、分镜与图片，结合时间、机位、走位、动作、视角和剪辑需要，自行在 `分镜.md` 标记并重试；只在缺少会影响结果且无法合理推定的信息时询问用户。命令本身不调用语义模型，脱离创作代理独立运行时会报告待判断，不会自称全部自动解决。
- 分镜记录独立或续接的实际理由；续接时核对机位、动作、道具与声音，连续画面可由多个 MOTION 接成。需要续接时移除构图参考并同步正式文档。
- 规划成功只更新 `视频提示词.md` 中对应的 `续接来源` 和 `H3自动续接` 记录，不改复制提示词正文。当前代理必须回读并按最终方案调整各段承接动作、运镜、对白和净时长，检查连续关系、独立切镜理由及人物位置；之后才执行快照、三阶段检查、分片、预览和登记。分镜变化须重新规划；自动记录和来源不一致时先查明人工修改，不能静默覆盖。
- 既有明确的 `续接来源：无` 或指定前段会保留，并非自动改成新方案。新批次的旧格式下，同场相邻独立段若没有明确切镜提示、构图约束或 `H3接续策略：切镜` 及理由，`prepare` 会要求当前代理复核；这一步不修改原决定。新任务经判断确需调整既有独立段时，在任务授权内将该段改为 `续接来源：自动` 并重规划，记录原因和新快照，不改写历史批次。同集有活动或释放状态未确认的批次时，规划器拒绝实际改写正式文档；旧批次 `resume/release` 仍沿原快照执行。需要只规划一个范围时可重复传 `--entry MOTION-...`；续接前段尚未规划时须同时纳入范围。所有分片使用同一完整链，避免运行中修改快照。
- `prepare` 会再执行一次规划以防遗漏。若因此改变正式文档，原专项输入 SHA 失效，入口会要求按新输入重新做真实阶段检查和记录后再准备；这是现有快照保护，不是新增用户确认。最终核查编译预览中的 `continue_from_job`、上下文、净帧和同实例串行安排。

角色新音色默认按 [Breeze TTS 2 SOP](../Breeze-TTS-角色音色SOP.md) 先理解人物、设计样音，在 Colab L4 自托管生成、取回释放并听核后绑定普通 `参考音频`；优先复用本作品同角色已采用 WAV。专项审查核对角色、来源、SHA、听核状态、用途边界与音频编号，H3 回片仍须另核实际音色、台词和接缝。旧批次按原快照恢复。完整阶段与技能见[连续执行 SOP](../autonomous-execution-sop.md#12-从剧本到交付)。

## 预检常见坑点

- **默认 Breeze 参考音频**：H3 开机前已完成样音听核，正式 WAV 路径、角色和 SHA 与实际绑定一致。缺文件先回 Breeze SOP，听感未核不能靠技术校验代替。
- **独立起段与续接**：Sequence 首段独立；之后只有分镜标明「入段：续接」才引用紧邻前段，实际成片可以没有切点。
- **续接链不绑构图参考**：构图例外只给完全独立 Motion 的起镜。续接链首与链内段的冲击帧用于导演对照。
- **三阶段 SHA 与图片验收指纹随上游改动过期**：三阶段输入 SHA 覆盖五份文档+资产字节，图片验收来源 SHA 含视觉设定/图片提示词条目。任何上游改动都使旧记录失效（报「专项检查记录过期」「验收证据缺失或已过期」）。**五份文档与资产定稿后再记录三阶段 SHA 与图片验收；改动后必须重取 snapshot、重算受影响 fingerprint 刷新索引，再 prepare**，把「改文档→重取 SHA→刷新验收」作为固定收尾步骤。

## 新批次的节奏与冲击帧检查

在正式准备、登记和开机前执行[冲击帧与节奏规则](../project-rules.md#visual-pacing)。检查结果写入原有三阶段字段。

打斗通过同一 `skill --stage` 入口加载各阶段的打斗小节。按回合核分镜、逐拍核动作与声响，取回后按原生时间码看片；结果沿用正式文档和现有专项审查记录。

核实际编译帧数与去重净片，确保关键切点、动作结果和收声在窗口内。合拍多镜检查模型的实际切点及动作相位，独立补拍检查接缝两侧，图像续接实验还要看首帧之后的方向和运动。整套配方对照记录实际请求、补拍、可用时长、资源耗时和响度差；要判断某一组件的效果时使用单变量对照。

- **storyboard** 核成片高点和状态交接。已选冲击帧写清配图理由、时点及用途。新集首批核整集节拍，后续批次及局部补拍核适用范围。
- **prompts** 把构图关系、动作起点和信息先后写进对应 `MOTION-*`。送 H3 的冲击帧写清只控制的起镜关系。核方向、道具状态、动作后果、文戏/打斗选档、起声及净可见区。
- **review** 对照[冲击帧验收](../image-generation-sop.md#visual-pacing-image-review)记录，核已选图的文件、来源指纹、实际画面和该时点的信息边界。只有完全独立 Motion 的起镜可挂图。

正式入口校验三阶段记录和已绑定参考的验收指纹。是否需要冲击帧由执行者按分镜判断，取回后按[节奏 SOP](../visual-pacing-sop.md)核实际开场、揭晓时点、动作后果、续接及对白。

新 V4 批次前，需要对本次选定范围完成分镜、提示词和专项自检。已有文档可回读核对，无须重写或重新生成。运行以下只读命令，取得实际范围和当前输入 SHA；有 `--entry` 时，快照与准备命令使用相同镜头范围：

```bash
python3 scripts/h3_production.py snapshot --project '<作品目录>' --episode EP001
python3 scripts/h3_production.py lint --project '<作品目录>' --episode EP001
```

在当前作品既有 `创作者决策/项目约定.md` 中以以下格式记录。每行用对应 `skill` 输出的 SHA 和真实检查结果；下面是格式占位，不是验收记录。一个阶段可用代表性镜头说明已落实的规则，审查覆盖应与「生成段」范围一致（旧记录「镜头：MOTION-*」兼容读取）。

```markdown
### forest-laoli-h3 · EP001
- 生成段：<直接采用 snapshot 输出，MOTION ID 用空格分开>
- 输入 SHA256：<snapshot 输出>
- storyboard：<该阶段 SHA256> SHOT-EP001-001 <实际采用的规则或检查结果>
- prompts：<该阶段 SHA256> MOTION-EP001-001 <实际采用的规则或检查结果>
- review：<该阶段 SHA256> MOTION-EP001-001 <自检或审查结果、保留风险及依据>
```

[项目 H3 专项入口](../../scripts/h3_production.py) 在 `prepare`、`preflight`、`register`、`run` 校验三阶段、范围与指纹，再调用对应执行版本的编译器或生产预检。输入指纹覆盖项目档案、剧本、视觉设定、分镜、视频提示词及范围内已绑定的图片和音频字节；文档、素材或技能资料版本变化时，复查并登记当前范围。工厂分批可复用覆盖本批的较大范围审查，但必须重算原审查完整范围的指纹并核对三阶段记录，不能只验证子集后宣称原审查仍有效。程序核验记录与版本，创作判断仍以文档和审查证据为准。

预检会拒绝首尾帧图片用途、非参考模式、同段多张构图图、续接链使用构图图，以及 MOTION 参考与其覆盖 SHOT 的用途并集不一致。每张绑定图片都要有当前用途、文件及正式来源的验收证据，记录方法见[生图 SOP](../image-generation-sop.md#41-h3-引用的图片验收)。文本 lint 只提示六段结构、主体与参考绑定、说话人和声画时序。专项审查负责判断冲击帧是否确有必要、同步声是否按剧本触发反应。

新任务通过[工厂手册](../factory/README.md#3-h3-统一排产与总预算)的 `episode plan → task create/prepare/run` 统一排产并调用上述预检；不另写单集运行脚本。任务续做按账本使用原执行版本。专项命令及参数见 [V4 执行配置](workflow-v4-colab-adaptation-20261110.md)，阶段位置见[总 SOP](../剧集制作总SOP.md)。
