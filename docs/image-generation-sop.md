# 生图 SOP · Codex 内置 imagegen

新任务由 Codex 内置 image_gen 生成图片。
本文件定义项目生图执行方式和资产交付要求。Drama Skills 继续负责创作与阶段编排。
新生图统一应用[生图提示词、看图与返修 SOP](image-craft-sop.md)。写实戏剧图按镜头卡写，人物、地点和道具板按各自识别及复用职责应用。
确认口径按 [连续执行 SOP](autonomous-execution-sop.md)：用户生成指令即任务授权，预览后直接执行；只有用户明确指定的确认点才等待回复。

本流程对应[总 SOP 第 7–8 步](剧集制作总SOP.md#7-图片提示词资产生图与实图验收)。新任务用[工厂资产入口](factory/README.md#4-原生生图与资产回绑)登记正式 IMG 的 `call prepare → dispatch → 当前宿主实际调用 image_gen → result → register → 实际看图 → observe → select`。共用入口管理回执、版本和引用，不能代替原生工具或实际看图；下文预检和画面要求仍须执行，不新增单集生图脚本。

## 1. 输入与职责

- `short-drama-image-prompts` 维护 `图片提示词.md` 中可复用资产与冲击帧的 `IMG-*`。可复用状态变体归资产，额外镜头图按冲击帧规则制作。
- `short-drama-storyboard` 维护`SHOT-*`的镜头状态文字与资产绑定；冻结关键帧不是图片任务。
- `short-drama-produce` 组织本批准确预览并核对任务范围；依据任务授权使用 `imagegen` 技能，
  在当前会话调用内置 `image_gen` 工具生成或修改图片。
- 使用用户已采用或执行者按任务授权检查后选定的版本，记录两者区别；修正提示词先更新正式文档，不悄悄改人物、造型或剧情约束。

### 1.1 资产设定与提示词交接

先实际读取 `short-drama-assets`、`short-drama-image-prompts` 的阶段契约和本次资产类型对应的 references。人物资产必读两边的 `character-and-look.md`，以及 `short-drama-image-prompts` 的 `production-sheet-recipes.md`。场景、道具、状态变体分别用各自的参考规范。对照剧本和本次复用目的完成下列检查后再交给 `short-drama-produce`。

| 资产 | 交接前核对 |
| --- | --- |
| 人物、造型 | 稳定识别锚点归人物。单立当前相容造型，说明所属人物及生效范围。服装层次、穿法、鞋履和服装锁归造型。手持剧情道具单列；身份板只放为识别所必需的物件。 |
| 地点 | 定朝向、空间锚点、光源与时段。地点板默认空场，有必要才派生不同视角。 |
| 道具、状态 | 定外形、尺度、可操作部位和当前状态。明确画中文字是可读、留白还是由后期添加；不混入另一时段的状态。 |
| 风格、构图 | 写清具体的视觉方向或镜头依据和控制范围。构图例外按下一节执行。 |

`IMG-*` 须用一行 `视觉依据` 指向 `视觉设定.md` 的具体二级标题，用全角分号分隔。人物图同时列人物和当前造型，`造型` 条目内写 `所属人物：角色名`，值与人物标题里的名称一致。例如：

```markdown
## IMG-EXAMPLE · 人物造型参考
- 用途：人物身份与当前造型
- 视觉依据：人物 · 角色名；造型 · 该角色当前造型
- 参考：无外部参考
```

地点和道具分别写 `地点 · 标题` 和 `道具 · 标题`。纯风格资产可写 `项目视觉方向`，独立镜头构图参考写实际 `SHOT-*`。上游字段与提示词格式继续适用。检查 `IMG-01`、`IMG-03`、`IMG-13` 等要求，服装锁原样带入正文。逐条判断构图能否显示要锁定的特征，人物资产采用下面的固定版式。

同场正反打以已采用造型或实际画面核领口、衣料纹样、发饰和耳饰，再补缺失视角。处境变化另立同一人物的相容造型变体，写清衣物破损、湿污、发妆和身体状态；按计划景别看这些变化是否可读。回绑时核每个 Motion 实际消费的身份与造型，不能仅凭提示词出现角色名推定已绑定。

**视觉依据两种格式不要混用**：图片提示词用标题式 `人物 · 角色名；造型 · 对应造型`（`image_assets.py` 按视觉设定二级标题匹配，每位出图人物须配一套所属造型）；分镜用引用式 `《视觉设定.md》·人物「角色名」（控制：身份）`。图片提示词照抄分镜引用式会报「视觉依据未定位到正式条目」。

#### 人物资产版式

**一个角色、一套造型、一张图。** 每个 `IMG-*` 人物资产在同一画布放三张全身视图和一张大头照。新生成和本次新选用的角色身份板都按以下要求验收。

1. **三视图**。正面、侧面、背面各一张，从头到鞋完整入画，比例和造型一致。所有可见的面部区域完全遮挡，任何视图都不露眉眼、鼻口等五官。保留头部外轮廓、发型、体态和服装细节。**遮脸必须写明具体遮挡物**（如 solid black cloth mask 黑面罩、帽檐压脸），不能只写抽象的 "face fully covered"——模型对抽象遮脸执行不稳定，曾出现正/侧视图露脸（EP002 副官/富豪板）。验收逐视图核五官不可见，露脸即未通过、强化遮挡物重生成。
2. **大头照**。独立留出足够大的头部区域，清楚呈现同一角色的完整面部、五官、脸型、发际线和辨识细节。使用同一造型的发型、妆容和可见配饰。
3. **提示词和验收**。在 `### 可复制提示词` 中明确写出四个视图、三视图全遮脸、大头照保留面部细节、四视图保持同一人物和造型，以及无视图标签、引线箭头、尺寸标注、图注。提交前核对这些要求，出图后按实际图逐项验收。缺视图、露出五官、裁掉全身部位或大头照细节不足时，记为未通过并修订。

H3 回绑时，整张板占一个图片槽。三视图提供体态和造型，大头照提供面部身份。三视图上的遮挡仅用于参考板，视频中是否遮脸按剧情与分镜执行。

<a id="h3-composition-reference"></a>

### 1.2 H3 构图参考

只有[符合条件的冲击帧](h3/shot-motion-contract.md#冲击帧与-h3-构图参考)可作为额外镜头构图图。完全独立 Motion 的起镜最多挂一张。分镜与视频提示词同步 `用途：构图` 的真实 `REF-*`，标明只取哪些画面关系。镜中揭晓的终态图用于导演对照，提示词负责描述揭晓过程和时点。

<a id="visual-pacing-image-production"></a>

### 1.3 冲击帧

按[分镜标记的时点和用途](visual-pacing-sop.md#冲击帧)制作。新图使用正式 `IMG-*`，用途字段沿用「视觉定调」，`视觉依据` 引用正式 `SHOT-*` 和相关设定。可复制提示词写画幅、必须读清的关系及当时实际可见的状态。复用图按当前镜头意图验收，拟送 H3 的图同时执行第 1.2 节。

**冲击帧含主角或需辨识的配角时，制作图片须挂对应身份板**，并在正文锁定身份描述（种族、脸型、疤、造型）。多角色同框按各自身份绑图。视频按实际出现的角色复用身份板。

## 2. 预览后连续执行

实际读取 `short-drama-produce` 和 `imagegen` 后，从项目入口取得当批精确预览。每个 `--entry` 对应一张拟生产资产或变体。预检退出非零时退回对应 owner 修订；预检通过后，执行者仍逐项核对上一节的内容、参考职责和取景，再将原文送给工具。

```bash
python3 scripts/image_assets.py preview --project '<作品目录>' --episode EP001 --entry IMG-EXAMPLE
```

每批先核对并保留以下完整预览；会话简要告知范围、变化、费用未知项及正式条目位置，不为预览调用生图，不默认等待回复：

| 项目 | 必须说明 |
|---|---|
| 来源 | 当前正式 Markdown 路径、`IMG-*` 正式条目及完整可复制提示词 |
| 执行入口 | Codex 内置 `image_gen`；不套用旧 `gpt-image-2` profile |
| 范围 | 每个资产/变体的数量、本批总数；每个资产或变体独立调用 |
| 参考输入 | 真实路径、顺序、身份/构图/风格等职责、允许与禁止控制范围；无图时明确无图 |
| 画面要求 | 用途、画幅、风格、光源、关键构图、精确文字及要保持的识别特征 |
| 输出 | `剧集/<EP>/制作成果/images/<稳定ID>.png` 等实际格式路径；默认不覆盖 |
| 能力与费用 | 只承诺当前工具支持的参数；未提供底层模型或报价时明确未知，不声称免费 |

用户已要求生成时，预览后直接执行整项任务，不逐图或逐批请示。任务范围内改提示词、输入、数量、输出或执行参数时，
更新正式文档和预览后继续；不突破用户明确的数量、预算、风格及必须保留项。用户指定“先看这批再确认”时才等该节点回复。
“继续”延续已定位的未完成任务；仅修改 SOP、只写文档或只检查时不启动生图。

内置工具参数以当前工具定义为准：画幅、精确像素等未暴露的选项只能作为提示词要求，
不能声称是硬参数或保证精确输出。不得自行加入 API 的 `model`、`size`、`quality`、`n`
或目标保存路径参数。

## 3. 调用与参考图

1. 无参考的新图使用内置工具生成；有参考/改图时，先用 `view_image` 查看本地真实图片。
2. 图片都有本地路径时使用 `referenced_image_paths`；否则按当前工具规则使用最小范围的
   `num_last_images_to_include`，两者不并用。不能包含全部所需图片时，先补齐输入，不静默漏图。
3. 保留正式文档的参考顺序与控制边界；`PLAN-*`、另一角色的图或未采用候选图不能冒充真实锁定素材。
   新增参考职责须先回到 owner 更新正文，再刷新预览并按任务授权继续，不另设确认关。
4. 改图明确“改什么、保留什么”，保留现有透明度；需要透明背景时使用工具的透明背景选项。
5. 每个资产或变体独立调用；不因批量需求切换 CLI，也不把多项独立资产拼成一张图充数。
   同一人物同一造型的三视图与大头照组成一项资产，同一道具的多视图亦可组成一项资产。

## 4. 入库、检查与回绑

1. 展示工具真实结果，从返回的实际文件路径复制所需输出到本集 `制作成果/images/`。
   默认生成位置在 `$CODEX_HOME` 下，不能猜文件名或只把项目素材留在工具默认目录。
   若当前工具未返回可访问文件，先取回原结果，不声称已入库或重新生成。
2. 使用稳定`IMG-*`资产ID命名；已有文件另存 `-v2` 等版本，覆盖必须明确授权。
   扩展名须与真实格式一致。
3. 核对实际尺寸、画幅和格式，用 `view_image` 逐张对照正式设定和提示词。人物板按[固定版式](#人物资产版式)检查四个视图，其他资产按用途查手持物、空间锚点、道具状态或文字。按[技法 SOP](image-craft-sop.md#生成后期与复盘)核光、材质、焦点和空气，记录实际结果。失败或未核对的图保留为候选，由上游负责人按主要问题修订并复验。
4. 图片通过检查后，执行者登记验收证据。实际绑定 H3 的图由分镜 owner 按任务授权将 `PLAN-*` 换成真实 `REF-*`，同步图片、顺序、用途及控制边界。供导演对照的冲击帧按第 4.2 节记录。
5. 每次更新相关正式文档运行 `bash scripts/drama check 剧集/<EP> --partial`；
   五份齐备改用完整检查。不为通过检查补造文档；任务目标包含视频或成片时自动续做，只要图片时止于图片交付。

### 4.1 H3 引用的图片验收

本集实际要绑定的图片按用途验收，生成资产用本集 `IMG-*`，已存在的合格资产可填 `复用` 并在观察说明中写明来源和本镜适用性。当前集制作成果目录下按 `IMG-*` 命名的图片须引用对应的正式条目。新生成的身份、地理和构图参考分别核对人物或道具、地点和镜头来源。

```bash
python3 scripts/image_assets.py fingerprint --project '<作品目录>' --episode EP001 \
  --path '剧集/EP001/制作成果/images/IMG-EXAMPLE.png' --purpose 身份 --source IMG-EXAMPLE
```

命令打印图片路径、用途、图片 SHA、来源、来源 SHA 和 `待核对` 状态。实际验图通过后，在作品现有 `创作者决策/项目约定.md` 的 `### 图片参考验收 · EP001` 下粘贴输出，把状态改为 `通过`，并在最后一个 `|` 后补上本次实际观察及适用范围。失败写 `未通过` 并说明缺陷。命令只计算指纹，检查结论由执行者填写。同一文件服务多个用途时分别验收。图片、用途、相关设定、`IMG` 正文或其参考图变化时，只复查受影响项。

H3 正式入口在 `prepare`、`preflight`、`register` 和 `run` 核对验收记录，未通过或已过期时暂停相关批次。已存在的好图可以据实补验，已启动的历史批次继续按原账本恢复。

新工厂的 `register/observe/select` 记录已接入同一 H3 校验。文件、用途、当前视觉来源、真实观察及选用均有效时可直接复用。既有指纹行继续兼容。供导演对照的冲击帧按第 4.2 节登记。

<a id="visual-pacing-image-review"></a>

### 4.2 冲击帧验收

供导演对照时，使用现有 `fingerprint --purpose 效果`，本集正式图的 `--source` 传实际 `IMG-*`，符合第 4.1 节的既有复用图可填「复用」。实际看图后在同集「图片参考验收」登记 `SHOT-*`、时点、构图关系及此时应遮住的信息。绑定为 H3 构图参考时按第 4.1 节以「构图」验收。

相关镜头投产前按分镜核本批已选冲击帧。图或来源有变化时复算指纹并复验。执行者判断配图必要性及画面，H3 入口自动核验已绑定参考。

## 5. 记录、异常与恢复

- 内置 `image_gen` 是会话能力，不是可由 shell 调用的 provider adapter。
  此路径不执行供应商的 `produce prepare/confirm/run/collect`；工厂 `asset call` 只登记宿主真实调用与返回，不伪造 provider job、确认回执、供应商 ID 或成功状态。
- 本次任务授权、预览告知和原生工具结果保留在会话；实际文件进入项目，创作引用写回原有正式 Markdown。
  续做索引只记录当前位置与下一步，不新增平行 JSON 剧本、单集交接文件或第二套生产账本。
- 中断或结果不明时先核对当前调用结果、实际输出和已入库文件。能取回原结果时直接取回；
  无法确认完成时报告未知，不把 API 的 `status/audit/collect` 当作原生工具恢复命令。
  需要重新生成时先说明原因、刷新预览，按连续执行 SOP 在任务范围内有限修正，不逐次索要批准。
- 内置工具不可用或失败时如实报告；不自动切换第三方 provider、Key、模型或 OpenAI API/CLI。
  视频、配音、音乐继续按 `AGENTS.md` 第 7 节使用官方 adapter 账本与恢复命令。

修改 SOP 不触发实际生图；只有真实执行后才能报告该批生成、入库和画面检查结果。

## 6. 平台横竖封面

任务包含投稿封面时，先读取平台当前的比例、尺寸和裁切要求。横版、竖版分别设计单画面海报构图、人物位置和标题层级，沿用本作品已采用的身份与视觉方向。人物组合参考板按前文管理，发布海报按该平台的展示用途验收。

- 正式提示词记录封面用途、画幅、逐字片名、参考来源和标题安全区；分别登记横竖图，生成后实看、入库并记录选用。已有合格封面可按任务范围复用。
- 在完整图和实际列表缩略图尺寸核片名无错字、字形清楚、人物身份与情绪可读，标题不遮住关键表情。横竖图分别检查，单纯裁切须证明两种比例都满足用途。
- 上传后核页面横竖封面卡片及实际预览，确认裁切、题字与保存状态。替换视频或封面后重新回读；封面检测和作品检测分别登记，等待发布按用户指定停点执行。
